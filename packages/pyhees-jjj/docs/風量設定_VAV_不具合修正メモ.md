# 風量設定・VAVの不具合修正メモ

## 1. 目的と対象

このメモは、既存JJJの風量設定ロジックを別プロジェクトの本番環境で運用している
担当者が、影響の有無を判断し、同じ修正を安全に移植できるように残すものである。

- 確認日: 2026-08-05
- 対象: `jjjexperiment` のダクト式セントラル空調関連経路
- 建研由来コード: 数式は変更しない
- 修正場所: JJJ拡張境界、入力検証、最低電力拡張、新床下逐次計算への受渡し

## 2. 結論

次の4点を確認した。AIR-01、AIR-02、AIR-04は修正し、AIR-03はExcel床下14の
数値契約を変えるため、独立した仕様判断事項として保留した。

| ID | 事象 | 影響条件 | 修正 |
| --- | --- | --- | --- |
| AIR-01 | サーモOFF・小負荷時に設備最低風量を下回る | `VAVあり × 全般換気なし` | 式 (43) と上限処理後に暖冷房期の設備下限を保証 |
| AIR-02 | 最低電力の補間点が0風量になる | `最低電力直接入力あり × 全般換気なし` | 全般換気量でなく `V_hs_min` を最低点に使用 |
| AIR-03 | 新床下は通常経路と異なり固定面積比を使う | `新床下あり × 負荷依存VAV配分` | **保留**。Excel床下14 Goldenを優先 |
| AIR-04 | 上限と下限が逆転した入力を受理する | `V_hs_min > V_hs_dsgn` 等 | 有限性、正負、大小関係を入力エラーとして検出 |

## 3. AIR-01: VAVあり・全般換気なしの最低風量

### 修正前

全般換気なしの場合、熱源機が搬送する換気量を0にする。これは正しい。しかし、
式 (43) の区画下限にも同じ0が入り、VAVありではサーモOFF時に合計風量が0、
小負荷時には設備最低風量未満となっていた。

確認例では、設備最低風量160 m³/hに対して次の結果だった。

| 状態 | 修正前 | 正しい下限 |
| --- | ---: | ---: |
| サーモOFF | 0 m³/h | 160 m³/h |
| 小負荷 | 4.141815772 m³/h | 160 m³/h |

VAVなしではVAV前風量がそのまま使われるため、同じ問題は発生しなかった。

### 原因

`V_hs_vent` と `V_hs_min` の責務が計算境界で混同されていた。

- `V_hs_vent`: 熱源機が搬送する全般換気量。全般換気なしなら0。
- `V_hs_min`: 暖冷房運転時の設備最低風量。全般換気なしでも有効。

### 修正後

建研由来の式 (43) は変更せず、JJJの風量上限処理後に、次の条件でだけ設備下限を
適用する。

```text
VAVあり AND 全般換気なし AND 暖房期または冷房期
```

不足分は区画別VAV前上限までの余地へ比例配分する。中間期は0のままとする。

## 4. AIR-02: 最低電力の補間点

### 修正前

最低電力式の最小側補間点に、変数名どおり `V_hs_vent_d_t` を渡していた。
全般換気なしでは0となるため、ユーザーが入力した最低風量で
`E_E_fan_min` に一致しなかった。

例として、最低風量160 m³/h、設計風量1500 m³/h、最低電力50 W、
定格電力300 Wでは、修正前の直線近似は最低風量点で約76.67 Wとなった。

### 修正後

最小側補間点を年間一定の設備最低風量 `V_hs_min` とする。直線近似・三乗近似の
どちらでも最低風量点が最低電力へ一致する。

実合計風量が0の時刻は式を評価して電力を残さず、ファン電力も0とする。
したがって全般換気なしの中間期に最低電力だけが計上されることはない。

公開関数 `get_E_E_fan_d_t` は既存呼出しとの互換性のため引数名
`V_hs_vent_d_t` を維持しているが、この拡張式へ渡す値の意味は
「設備最低風量の8760時間配列」である。移植時に変数名だけを見て全般換気量へ
戻さないこと。

## 5. AIR-03: 新床下逐次計算のVAV配分（保留）

### 確認した相違

通常経路で負荷依存の時刻別配分 `r_supply_des_d_t_i` を求めた後、新床下逐次計算の
入力作成時に固定面積比で再計算していた。このため同じ入力でも、新床下を有効に
した場合だけ `change_supply_volume_before_vav_adjust` の効果が失われた。

### 採否判断

通常経路の時刻別配分を逐次ソルバーへ渡す試行では、床下14 Goldenの暖房年間値が
43,035.60693062981 MJ/年から49,905.88294356516 MJ/年へ変化した。丸め差ではなく、
床下熱収支へ大きく影響する仕様差である。

今回はExcel床下14との一致を優先し、固定面積比を維持する。負荷依存配分を新床下へ
適用するかは、Excel側の配分規則を含めて別途対話・検証し、合意後に扱う。

## 6. AIR-04: 入力整合性

次の入力を明示的に拒否する。

| 入力 | 条件 |
| --- | --- |
| `V_hs_min` | 正の有限値 |
| `V_hs_dsgn` | 正の有限値 |
| 風量の大小 | `V_hs_min <= V_hs_dsgn` |
| 最低電力補間時 | `V_hs_min < V_hs_dsgn` |
| `E_E_fan_min` | 0以上の有限値 |
| 電力の大小 | `E_E_fan_min <= P_fan_rtd` |

修正前は、最低風量1200 m³/h、設計風量500 m³/hのような入力でも計算が進み、
区画下限を適用した後の一律上限で下限を再び破ることがあった。上下限が同時に
成立しない入力なので、どちらかを暗黙に優先せず入力エラーとする。

## 7. 影響範囲

| 設定 | AIR-01 | AIR-02 | AIR-03 |
| --- | --- | --- | --- |
| VAVなし・全般換気あり | 影響なし | 最低電力入力時のみ補間点明確化 | 保留・変更なし |
| VAVあり・全般換気あり | 影響なし | 最低電力入力時のみ補間点明確化 | 保留・変更なし |
| VAVなし・全般換気なし | 従来から下限成立 | 最低電力と中間期電力を修正 | 保留・変更なし |
| VAVあり・全般換気なし | **風量修正対象** | **電力修正対象** | 保留・変更なし |

年間エネルギー結果への影響は入力と発生時間数で変わる。特にAIR-01は、従来
ほぼ無風だった小負荷時の搬送熱量とファン電力を増やし得るため、結果差を
単なる丸め差として扱わないこと。

## 8. 本番環境への移植手順

1. 本番コードが `V_hs_vent` と `V_hs_min` を同じ変数として扱っていないか検索する。
2. `VAVあり × 全般換気なし` の式 (43) 後の合計風量を8760時間出力する。
3. 暖冷房期の下限と中間期0を別々に確認する。
4. 最低電力の2点補間に、全般換気量ではなく設備最低風量を渡す。
5. 実風量0の時刻にファン電力を0とする。
6. 新床下はExcel床下14の固定面積比を維持し、配分変更を混在させない。
7. 最低風量、設計風量、最低電力、定格電力の入力整合性を検証する。
8. 暖房期・冷房期・中間期の代表時刻と年間値を修正前後で比較する。

| VAV | 全般換気 | 負荷状態 | 期待値 |
| --- | --- | --- | --- |
| あり | なし | 暖冷房期サーモOFF | 合計風量 = 設備最低風量 |
| あり | なし | 暖冷房期小負荷 | 合計風量 >= 設備最低風量 |
| あり | なし | 中間期 | 風量 = 0、ファン電力 = 0 |

計算エンジン内部テスト、GitHub Actionsを最終判定とする。

## 10. 既知の別課題

全般換気なしの結合テストでは、建研由来コードが非稼働側・反対季節も配列として
先に評価するため、0風量除算の `RuntimeWarning` が発生する場合がある。今回の
AIR-01〜04より前から存在し、現行の出力選択では非対象季節値として使われない。

この警告の解消は、式の評価順やマスクを変更して数値結果へ影響する可能性があるため、
今回の修正へ混在させない。警告をエラーへ格上げする場合は、独立課題として
代表CSVと年間値を確認する。

計算ルートの全体像は [風量設定・VAV・全般換気の計算ルート](風量設定_VAV_計算ルート.md)
を参照する。
